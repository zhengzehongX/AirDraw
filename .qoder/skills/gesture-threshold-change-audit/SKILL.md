# Gesture Threshold Change Audit

## Overview

阈值改了、套件全绿、用户还在报同一句话 —— 这通常不是「还差一点数值」，而是那次改动被下游某个消费处吃掉了，或者测试用的那只手根本不是真人手，缺陷结构性地测不到。本 Skill 规定一套归因阶梯：先把症状钉到一个具体闸门，再读用户浏览器的实况，再追被改常量的每一个消费处，然后才允许动代码、动测试、动交付口径。

分工：`gesture-threshold-noise-probe` 负责**测量**（阈值该定多少、边界在哪），本 Skill 负责**归因**（为什么上一次改动没生效）。需要定量时按 Step 6 移交过去。

文中出现的常量、比例、条数都只是某次实测样例，禁止照抄 —— 一律 grep 现值。

## 何时使用

- 同一个症状被用户第 2 次以上反馈，而上一轮确实改了阈值且回归全绿。
- 用户说「改回之前的」「灵敏度调高些」「还是不行」——说明他们要的不是再一档数值，而是能自助。
- 需要区分「修复无效」与「修复未生效」：前者是算法方向错，后者是消费处覆盖。
- 准备为了让套件变绿而修改/删除一条断言之前。

不适用：首次定阈值（→ `gesture-threshold-noise-probe`）；UI 布局、文档、导出、性能类改动。

## 三条铁律

1. **症状第二次复现后，禁止再猜数值。** 每猜一次就是一次全链回归；改成流程问题来查（Step 1~3）。
2. **先算「有效值」，再宣布修好。** 被改常量在任何一条分支上被二次 `min`/上限校验处理过，那次改动就不算生效。
3. **跑绿的那只手必须是真手。** 夹具的隐含解剖比例要反算出来与真人对比；合成姿态的量级不等于摄像头的量级。

## 归因阶梯

### Step 1 提示文案 → 唯一闸门

用户能给出的只有那句文案。grep 文案字面量，定位产出它的分支及其全部条件，写成一句话「这句提示 = 这个条件」，动手前落在纸上。

```bash
grep -rn "指尖接近，尚未确认三维接触" src/          # 文案出自哪里
grep -n "reason" src/utils/gesture/PinchContactDetector.ts   # 每条 reason 对应的条件
grep -rn "insecure-context\|hint\|reason" src/components/     # 界面上还有谁在拼文案
```

样例结论：本项目该句在 `PinchContactDetector.ts` 里只对应 `d3Normalized > radius`，所以问题被钉死在「三维闸门」这一处，不需要怀疑投影、确认帧、速度门限。

若一句文案有多个来源分支，先拆成不同文案再继续 —— 否则下一次读数仍然无法归因。

### Step 2 读用户浏览器的实况，不是开发机的

开发机上复现不出来，最常见的原因是开发机有用户没有的状态。逐项读：

| 读什么 | 怎么读 | 说明什么 |
|---|---|---|
| 个人校准档案存在吗 | `localStorage.getItem('<校准 key>')`，如 `airdraw-pinch-calibration` | `null` = 这台机器**一直在吃默认值**；此前所有「走已校准分支」的假设都不成立 |
| 档案被判定为「已校准」吗 | 光有值不够：代码里通常是 `personal = typeof p?.calibratedAt === 'string' && Number.isFinite(Date.parse(p.calibratedAt))` | 缺 `calibratedAt` 的档案会被加载器拒收并静默回落默认值 |
| 闸门实际是多少 | 诊断读数，如 `window.__airdraw.inputDiagnostic.contact` 的 `state / d2Normalized / d3Normalized / zGap / radius / profile` | `radius` 与这只手的 `d3` 谁大，直接决定症状；`radius` 不等于你写的默认值（见 Step 3） |
| 拿不到实况 | 让用户 `?debug=1` → 「导出输入诊断」发回 JSON | 这是唯一能把体感问题变成数字的兜底；别再凭文案二次猜测 |

用 Qoder 的浏览器连接读用户已登录的页面即可；`evaluate_script` 一次把整组读数取出来，别逐个试。截图不可用时改用 snapshot / 脚本取值。

### Step 3 追被改常量的每一个消费处（这一步是归因主体）

沿一条链走到底：**定义 → 加载/校验 → 合并 → 每一个使用点**。任何一环都能把改动吃掉。三类已验证的失效形态：

| 形态 | 实例（本项目代码，数字为样例） | 后果 |
|---|---|---|
| `Math.min(default, heuristic)` 隐性收紧 | `m.radius = profile.calibratedAt ? profile.contact : Math.min(profile.contact, estimatedRadius)`，其中 `estimatedRadius = Math.max(.08, .3*(‖w3−w4‖+‖w7−w8‖)/palm)` | 真手（掌宽 85 / 食指末节 20 / 拇指末节 25 mm）算出 ≈0.159，把默认 0.22 压回 0.16 —— 上一轮改动**一行都没生效**，而且只在未校准分支生效 |
| 加载器区间校验过窄 | `loadContactProfile()` 对个人档案与默认值用不同上限（如 `contact <= (personal?.7:.36)`、`z <= (personal?.65:.25)`） | 放宽后的档案被判非法 → **静默回落默认值**，界面上没有任何异常 |
| 覆盖只作用于某一条分支 + 分支人口结构变了 | 把「强制前置校准」改成「可选」后，`offerCalibration = !calibratedAt && !skipped` | 只在已校准分支修的修复等于没修：未校准成了多数路径 |

```bash
grep -rn "DEFAULT_CONTACT" src/ scripts/        # 定义 + 每一个消费处
grep -n "Math\.min\|Math\.max\|clamp" src/utils/gesture/PinchContactDetector.ts
grep -rn "loadContactProfile\|calibratedAt" src/ # 校验与回落逻辑
```

判定与处置：

- 把该分支的**有效值**算出来（代入真实手比例），而不是引用你写进常量表的那个数。
- 让启发式/估计值**只允许放宽、不允许收紧**；收紧只能来自明确的用户意图（校准、辅助滑条）。
- 推导类档案（自校准会话产出的 profile）有自己的夹逼区间：默认值放宽后，`PinchCalibrationSession` 一类的上限必须同步放宽，否则用户自校准仍会拿到过紧档案，产品体感不会改善。
- 结构性出路优先于继续调数：把「单一硬闸门」改成**加权证据**，让噪声最大的那一维（通常是单目深度）按稳定度动态降权，而不是拥有一票否决。

### Step 4 用真实人体测量复核夹具

绿灯不等于可用 —— 先问跑绿的那只手是不是真人手。

```
真人：0.3 × (拇指末节 25 + 食指末节 20) / 掌宽 85 ≈ 0.159
旧夹具：同一公式 ≈ 0.203，且被夹在「高于收紧下界」的几何上
```

夹具落在真人做不到的几何上时，整套断言（本项目曾 732 条）**结构性地测不到该缺陷**：它绿在产品无法达到的区域里。补真实人体测量夹具（显式写出 mm 出处）后，两件事必须验证：

1. **有鉴别力**：把产品代码临时回退到旧行为，新夹具必须转红。旧代码下也全绿的夹具是摆设。
2. **两侧都有档位**：必须落笔的档位（真人可达，样例 0.13/0.19/0.21 palm）与必须不落笔的档位（样例 0.36/0.5/指尖深度错位）都要写进去，并在注释里留下测得的 d3 与对照 profile，供下次阈值再动时对照。

同时检查旧夹具在改动后是否已「落进接触带」——那属于夹具语义失效，不是产品缺陷，按 Step 6 处理。

### Step 5 改测试之前先给断言分类

| 类型 | 编码的是 | 放宽默认值时怎么处理 |
|---|---|---|
| 策略断言 | 某个具体数值档位，例：`default gate remains conservative` 断言 0.27 **不**算接触 | 随策略一起改。它测的是旧档位，不是安全性质，留着它只会把缺陷钉死 |
| 安全不变量 | 属性：张开手不算接触、深度错位不算、扫手不变成一次点击、确认帧不被跳过 | **任何档位都必须保留**，禁止为了变绿删除或放宽 |

样例改写（本项目 `scripts/contact-regression.ts` 现状）：一条 `remains conservative` 拆成
`default gate reaches a real pad-touch`（0.27 算）+ `default gate still rejects 36 mm apart`（0.36 不算）
+ `even fully assisted rejects a clearly open hand` + `assist never forgives a depth mismatch`。

**放宽必须伴随新的上界断言**，否则删旧断言等于删测试。同理新增辅助能力时要同时断言它「做不到」什么（辅助不放宽确认帧、不原谅深度错位）。

### Step 6 放宽之后复跑负向夹具

移交 `gesture-threshold-noise-probe` 执行测量：负向夹具（「接近但未接触」「30 次接近不落笔」）必须**实测**落在 NEAR 带，不能只看名字 —— 阈值一放宽，原本代表「差一点」的姿态很可能已经是一次真捏合。

样例证据：contact 提到 0.30 后，浏览器套件里「30 次接近不落笔」仍然通过（合成 near 姿态实测 d3 ≈ 0.316 > 0.30），这才允许放宽出厂。若它转红，先按那个 Skill 的复位阶梯判断是夹具语义失效还是真的误触，再决定改夹具还是回退阈值。

### Step 7 检查用户自救通道

默认值失灵时用户能不能自己救自己。三处必查：

1. **设置项是不是空实现**：grep 形参有没有被用到。空壳的典型痕迹是下划线前缀形参 + 一句「不能削弱闸门」的注释 —— 本项目的「捏合辅助」长期如此，直到接成真实生效（0→1 让距离与投影闸门再放宽约 45%、深度约 50%，**不**放宽连续确认帧）。
2. **文档承诺的控件在 UI 里是否存在**：USER_GUIDE / 说明书里写了滑条，而 `SettingsScreen` 里没有对应控件 = 用户无处可点。按文档核对流程逐条回代码核实。
3. **把前置步骤改成「可选」之后，多数路径变了吗**：可跳过的邀请（`offerCalibration = !calibratedAt && !skipped`）会让从未校准的人占多数，此时任何只在「已校准」分支生效的修复都等于没修。

### Step 8 交付口径

- 用一句话讲清**上一轮为什么没生效**（是被哪个消费处吃掉的），不要粉饰成「又调了一次阈值」。
- 给一条**不受这些常量影响**的路径：个人校准写下的是这只手自己的数字，直接绕开默认值与解剖估计；默认值失灵时它是最稳出路。
- 标注数字来源：「从合成手 d3 分布推出」≠「这台摄像头这只手量出」。后者没拿到就写明残余失灵范围，并明确请用户导出诊断，而不是继续调数。
- 日志写方法不写结论：失效形态、夹具 mm 出处、每条负向读数、断言条数改动前后。

## 陷阱清单

| 陷阱 | 后果 | 处置 |
|---|---|---|
| 再猜一档数值 | 三次改方向、症状不变、每轮一次全链回归 | 铁律 1；走 Step 1~3 |
| 只改默认值不看消费处 | `min()` / 上限校验让改动 0 行生效 | Step 3 逐消费处算有效值 |
| 在开发机上复现 | 开发机有用户没有的校准档案，永远复现不出来 | Step 2 读用户浏览器 |
| 把夹具几何当真 | 数百条断言全绿而真人失灵 | Step 4 反算解剖比例 |
| 新夹具在旧代码下也绿 | 摆设，下次仍然测不到 | Step 4 回退验证鉴别力 |
| 删掉「碍事」的断言 | 把安全不变量当旧策略一起删了 | Step 5 先分类 |
| 放宽后不复跑负向夹具 | 「接近」变成「接触」，满屏误触 | Step 6 |
| 按记忆/旧文档里的常量与条数动手 | 改到过期值、漏掉新增套件 | 每个数字都 grep 现值、先枚举再改 |
| 宣布「修好」但自救通道是空壳 | 用户刷新后仍然不行，第 N+1 次反馈 | Step 7 |
| 长时间回归期间编辑 `src/**` | HMR 中途重载页面，整轮数字作废 | 见 `airdraw-regression-verification` |
| 断言条数用 `grep -c PASS` 统计 | 描述文案含 PASS 导致计数虚高 | 以 `docs/verification/*.json` 产物为准 |
| 本仓库无 git | 删掉的夹具、临时快照不可恢复 | 动测试前先归档快照到不参与构建的目录 |
| 用 heredoc 写含 CJK 的探针/脚本 | 引号与反斜杠被 shell 吞掉 | 用文件写入工具创建脚本 |

## 验收清单

- [ ] Step 1 产出「这句提示 = 这个条件」的单映射，来自 grep 而非推断；多来源文案已拆开。
- [ ] Step 2 拿到的是**用户**浏览器的实况：校准 key 是否存在、`calibratedAt` 是否合法、`radius` 与 `d3` 的实测对比。
- [ ] Step 3 被改常量到每个消费处的链路全部走查（`min/max/clamp`、加载器区间校验、分支专属覆盖），有效值已代入真实手比例算出；估计类闸门改成只放宽不收紧。
- [ ] Step 4 夹具隐含解剖比例与真人对比过；新增的真实人体测量夹具在旧代码上会失败（有鉴别力），正/负档位都写入了实测读数。
- [ ] Step 5 每条被改动的断言已分类；安全不变量一条没少；每个放宽处都新增了对应的上界断言。
- [ ] Step 6 负向夹具实测为 NEAR、正向夹具实测为 HOLD，确认帧与深度门限未被放宽。
- [ ] Step 7 自救通道真实存在：设置项参数被使用、UI 有对应控件、文档描述与实现一致，且未校准这条多数路径也修到了。
- [ ] Step 8 交付里写了根因与数字来源，并给出不依赖默认值的出路（个人校准）。
- [ ] 回归按项目 verify 顺序跑完（离线核 → 浏览器套件 → 必要时长跑），长测期间未修改 `src/**`，条数取自套件自身产物。
- [ ] 若同一轮动过 README / USER_GUIDE 的阈值或能力描述，已按文档核对流程逐条回代码核实。

## 与其他 Skill 的分工

- 要**测量**阈值边界、跑位移阶梯、对齐各套件预置校准值 → `gesture-threshold-noise-probe`（本 Skill 的 Step 6 直接接过去）。
- 要跑交付前回归编排、判断某轮长跑为何作废 → `airdraw-regression-verification`。
- 要把改动写进日志/README/USER_GUIDE → `verify-doc-claims-against-code`。
