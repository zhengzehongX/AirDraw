# 第八阶段交接：摄像头、连续输入与语音

日期：2026-10-06。基于用户完善后的第七阶段原架构渐进修改，保留 DrawEngine、StrokeStore、工程系统、三模式、PlayLab、教程、Gallery、Help、主题、保存与导出。未推倒重写，未创建第二套语音菜单。没有 Git 元数据可用于提交差异核对；以当前源码和测试报告为依据。

## 已完成

- 全局 CameraService 单一所有权、租约清理、合并启动请求、六帧预热、状态协议、页面恢复、track 异常恢复和有界重试；识别器重试优先复用仍有效的摄像头流。明确 Enter 后才打开摄像头，返回首页保持会话。
- Worker 优先真实视频帧回调，20–30fps、最长边640 ImageBitmap、单个在途推理和忙时跳帧。本地GPU失败优先本地CPU，置信度与双手配置保留，同一实例 setOptions 更新。
- AdaptivePinchDetector 证据融合、个人校准、EMA、接触锁存、迟滞释放；兼容旧五态。DrawEngine 短暂缺失续写、长缺失/主手切换/异常跳跃终止；InputRouter 切换后等待明确松开，未确认 CONTACT 不可触发玩具抓取。
- 首次快速校准入口与 Settings 重新校准；保存设备、掌宽、距离、主手与指针敏感度。预览默认收起，骨骼保留，文字不镜像；HandFrame 非镜像，PlayLab 在展示边界映射。
- AppCommandBus 统一主要手势/语音动作，绘画中的撤销/保存延迟至提交，模式切换先释放输入；OPEN PALM 菜单也走同一处理器。危险确认阻止其它低优先级命令。
- VoiceAssistantService / SpeechProvider / WakeWordProvider / VoiceCommandRouter，中文确定性同义词、8秒唤醒窗口、实时短文本、独立麦克风权限、可选静音反馈、清空确认/取消、每分钟最多六次延迟重启。新唤醒可以打断成功反馈，避免连续命令丢失。
- 单次 Enter、品牌/快速开场、统一 BootPhase、GPU点轨迹、真实预热进度提示、Motion 退出过渡；工作区原图层保持挂载，同一 Canvas。顶部状态点与 Voice Pill，Settings 增加语音配置。软件 WebGL 检测后使用低视觉档，防止空场景帧率短暂提高后又升回重档。

## 部分完成

- 普通设置与视觉语言继续沿用 Design/Motion Tokens；旧面板布局、部分专用编辑回调和导航尚未全部迁移命令总线，不能称为全面 UI 重设计。
- 屏幕与对象跟随使用既有滤波/渲染插值；完整基于两个时间戳的 landmark 插值未实现。短缺失保持会话、不外推远距离点；可靠点恢复后安全续接。
- 英文识别语言可选择，英文语法仅 undo/redo/save；中文菜单覆盖完整基础命令。SLEEPING 是预留状态，当前 Web Speech 持续监听唤醒文本，不是真正低功耗离线唤醒。
- 专属的抽象指尖圆环与真实食指对齐动画尚未实现，目前接手原有空间光标；Canvas 模式已有模型仍可能遮挡画板，完整后移/淡化流转需要继续完善。
- 品牌配置初次1.5秒、返回0.75秒；加载与软件渲染争用时实际可交互时间会更长，不能将配置时长当作设备实测值。

## 未完成 / 验收边界

- 真实40/60/80/100cm、左右手、大小手掌、不同光照、30次轻触/明显分开、30秒连续书写的人手矩阵；已向用户请求反馈，尚无本阶段真实结果。
- 原生麦克风30条指令、噪声/口音/超时/权限恢复矩阵；自动化模拟 SpeechRecognition 事件，不能声称识别准确率。
- GPU/CPU 实际不同设备性能和完整30分钟真实摄像头/语音长跑。当前长跑使用合成手势与软件WebGL，真实CPU识别Worker在另一个回归中验证。
- Vosk、Porcupine 未接入；不硬编码密钥，不宣称默认语音离线。现有项目未安装 Remotion，按用户条件要求未增加 Composition，也未引入实时主链路。

## 参考、许可证与修改原因

参考官方 google-ai-edge/mediapipe-samples-web（Apache-2.0）Worker 架构；motiondivision/motion（MIT）沿用现有依赖；TalAter/annyang（MIT）仅参考命令映射。Vosk两仓库 Apache-2.0 与 Porcupine仓库 Apache-2.0 已核对，Porcupine Web要求AccessKey，未接入。各链接和使用边界见 [Camera架构](camera-architecture.md)、[Voice命令](voice-commands.md)。本阶段未复制来源不明代码。源码实际只使用现有 MediaPipe/Motion 及浏览器 Web Speech API。

改变原因：严格AND与单帧退出导致真人接触无法落笔、断线；重复视图所有权容易重启摄像头；语音直接访问组件会形成第二套控制。现在将识别、会话和命令处理分别集中，保留现有业务编辑模块。

## 下一步优先级

1. 首先完成真人接触矩阵；根据输入诊断调整个人校准，不把阈值当作绝对皮肤距离保证。
2. 排查软件/低性能GPU长帧，继续降低昂贵玻璃材质和预览开销，保持识别准确性；补全硬件60fps与长期资源曲线。
3. 补充完整 landmark 时间插值和所有专用工具总线迁移，减少 App.tsx 体积，完善移动窄屏布局。
4. 原生语音兼容、权限与噪声测试；再决定是否引入离线引擎并独立核对模型/服务许可。
