## 2. 应用状态机取代布尔量

第三阶段的界面由 12 个互相独立的布尔量拼出来，结果是**手势可以作用在用户根本看不见的界面上**：
收起的 Dock 仍然可命中、面板里的捏合同时在画布上落笔。第四阶段换成一个 `context` 加它的子状态：

```
launch → permission → tutorial → studio ⇄ { help | gallery | settings }
```

| context | 可命中的区域 | 笔能否落下 |
| --- | --- | --- |
| launch | `launch-begin` | 否 |
| permission | 无（只有浏览器系统框） | 否 |
| tutorial | 教程目标 +（绘画课时）画布 | 仅第 4、5 课 |
| studio | Dock（张开手掌时）、主题、摄像头点 | 是（悬停控件时自动抬笔） |
| help / gallery / settings | 各自 scope 内的区域 | **否**（模态，背后一律不命中） |

派生规则集中在 `appState.ts` 的 `canDraw()` / `activeScope()`，并在 `scripts/selfcheck.ts` 里
用纯逻辑断言钉住（14 项），新增界面无法悄悄开出一条落笔通道。

区域隔离的实现：`InteractiveRegion.scope` + `setActiveScope()`，命中测试只接受当前 scope 与全局区域；
`register()` 的注销改为按对象身份判断（StrictMode 重挂载或同名界面切换时不会误删活区域）。

## 3. 首次启动与 Hello 粒子

- 开场只有 Logo、`Draw in the air.` 和一个入口。**没有自定义权限框**：权限一律交给浏览器系统框。
- 若 `permissions.query({name:'camera'})` 已经是 `granted`（老用户），开场就启动追踪，
  入口可用**捏合**完成；否则只接受点击，避免在解释之前就弹权限框。
- 两次确认：第一次让粒子聚合为 `Hello!`，第二次向外爆散并淡出，同时进入下一步。
  粒子是一个 `THREE.Points` + 自定义 shader（漂浮→错峰聚合→爆散），
  文字目标点由离屏 2D canvas 采样像素得到；三个阶段都是"目标值 + 每帧阻尼"，
  因此**任意时刻都能被打断**，不做硬切。低端设备与 `prefers-reduced-motion` 下减少数量与位移。
- 完成教程后不再重播：`helloSeen` / `tutorialDone` 决定下次直接进画布或教程。

## 6. 作品管理

- `storage/artworks.ts`：IndexedDB（`airdraw` / `artworks`，keyPath `id`，`updatedAt` 索引）。
  记录包含 `schema`、标题、创建/更新时间、笔画数据、画笔（颜色/粗细/材质）、日夜主题、
  相机状态（yaw/pitch/distance）、笔数与点数、以及 PNG 缩略图 data URL。
  IndexedDB 不可用时退回内存并照常工作（不再静默失败）。
- 旧的 `localStorage` 单笔存档在首次进入时自动迁移一次并删除原键。
- 作品库：大留白卡片（缩略图 / 标题 / 相对时间 / 笔数），打开、复制、导出 PNG、导出 JSON、删除；
  **删除必须长按约 1 秒确认环**，短捏只会浮出确认；确认期间其余目标一律禁用。
- 导出 PNG 走离屏 `renderToDataUrl`：临时提高 pixelRatio（高分屏 2×）、
  可选透明背景或当前日夜背景，在同一任务内回读，结束后完整还原尺寸/背景/clearAlpha，
  因此不需要常驻 `preserveDrawingBuffer`。
- 画布不再自动回填旧笔迹：只有从作品库明确打开某件作品时才会载入。

## 8. 异常处理与性能

- 能力探测：无 WebGL / 无 `getUserMedia` / 非安全上下文分别给出精确页面与恢复步骤，不再白屏。
- 失败状态页覆盖：权限被拒（含地址栏逐步恢复说明）、无摄像头、被占用、约束不支持、
  模型加载失败、非安全上下文，全部带"重试"（重试同样可用捏合完成）。
- 性能模式：governor 降到最低档时提示一次 `Performance mode enabled`；
  降级只作用于泛光、环境探针、DPR、tube 细分与粒子数量，**不触碰识别阈值**。
- 手部短暂消失：冻结 UI 输入、取消未释放的按压、结束当前笔画，恢复后要求重新建立指向状态。

## 9. 本阶段修掉的问题（按影响排序）

1. **普通用户根本打不开摄像头**：唯一的 `<video>` 挂在开发者预览里，而预览只在
   `previewExpanded || devMode` 时渲染；不带 `?debug=1` 打开时 `videoRef.current` 为 null，
   启动即抛错并停在"举手开始"，且不显示任何错误。第三阶段的自动化测试恰好一直带着 `?debug=1`，
   所以从未暴露。现在摄像头源由追踪 hook 自己持有（1px 常驻、不可交互），
   预览退化为流的另一个视图，隐藏或删除预览都不再影响识别。
2. **橡皮擦绕过全部锁定**：擦除读的是未过闸的 `pinchedRaw`，握拳、查看模式、
   甚至捏合 Dock 按钮的同时都会删掉笔迹。现在与落笔共用同一道 `penPinched` 闸门。
3. **笔刷滑杆无法用手势拖动**：`useInteractive` 返回的 `ref` 没有挂到被测量的元素上，
   区域永远量不到矩形，捏合永远命不中。改为共用同一个 ref。
4. **长按清空经常被吞掉**：确认浮层同时被 CSS `transform: translate(...)` 与
   framer-motion 的 `scale` 写入，动画期间命中框漂移，长按进度不断被重置；
   同时浮层压在 Dock 按钮上，面积更小的按钮抢走了命中。现在浮层位置稳定、
   确认期间禁用其余 Dock 目标，并在动画结束时重测矩形。
5. **长按完成后紧接着画出一笔**：确认浮层消失后手指仍捏着，落笔闸门以为用户在画布上捏合。
   现在点击冷却期内同样抬笔（一次捏合只允许有一个后果）。
6. **教程第 10 课无法完成**：VICTORY 被限定在 studio，教程里比剪刀手没有反应。
7. **教程第 5 课被第 4 课顺带通过**：新增 `penWasDown` 锁存，要求本课内真的重新落笔再抬起。
8. **进入查看模式时画面跳一下**：非查看态也在刷新双手距离基线，现在只在查看态累积。
9. **重采样抽稀会吃掉转角**：抽稀只按 stride 取样，转角节点被丢弃；
   第四阶段的墨量预算让抽稀更容易触发，汉字折角会变圆。现在抽稀强制保留 knot。
10. **收起的 Dock 仍可被捏中**、**面板在 Dock 关闭后残留**、**注销按 id 误删新区域**、
    **`flash` 定时器无人回收**、**动画中途测量矩形**等状态与生命周期问题一并处理。
11. 移除第二阶段的 `holdActions` 遗留模块与其配置项；修复 `polyline.midpoint` 缺 `z` 的类型问题。
12. **设置里的"开发者模式"不生效**：面板显示由 App 内另一个 `useState` 决定，设置只写偏好，
    两者从不汇合——用户拨动开关后什么都没发生，直到刷新。现在 `prefs.devMode` 是唯一真源
    （`?debug=1` 只在载入时播种一次、不写回用户偏好），开关立即改变面板、面板关闭按钮也写回偏好。
13. **Dock 会在用户"正在走向它"的过程中收起**：自动隐藏只看"光标离开 Dock 1.4 s"，
    而从画面中央到 Dock 外侧那一项本身就要 0.4–0.5 s 的光标收敛时间，
    慢一点的手或满载的机器上，指尖到达时 Dock 已经关上、远处那几项根本点不到。
    现在光标到 Dock 的距离在缩小时不开始计时（`src/App.tsx` 的 approach 判定）。
14. **导出 PNG 会吃掉当前画布**：为了拍照而把保存过的作品铺回画布，导完不还原——
    用户没保存的那一幅就没了。现在导出前后 `loadArtwork` 成对，画布与主题都恢复原状。
15. 自检脚本本身的两类不稳定：`gesturePose`/`waitForTimeout` 是"等时间"，
    在 2–16 fps 的合成手上会在识别确认之前就走完；改成"等状态"
    （`poseUntil`、`waitForFunction` 观察 `strokeCount`/偏好/面板），
    并给 Dock 按压加上"呼出→按压→再呼出"的重试。
16. **剪刀手一闪就进查看模式，然后笔再也落不下去**：VICTORY 原先只按"边沿"触发
    （`lastGesture !== 'VICTORY'`），而捏合扫过、握拳收指这些动作**路上就会经过**两指伸直的形状，
    3 帧确认（约 100–200 ms）足够误触发。进了查看模式笔是被抬起的，于是画布看起来"坏了"——
    这正是 30 分钟长跑里那一轮"周期全在画空"的真凶（`debugInternals.inspectMode` 一直为 true）。
    现在 VICTORY 必须**保持 `VIEW_MODE_HOLD_MS`（400 ms）**才切换，并且一次保持只切换一次；
    自检新增一条"两指一闪不算进查看模式"。

## 10. 产品化补齐（本阶段最后一次提交）

- **导出背景可选**：作品库底部 透明 / 日间 / 夜间 三枚手势可点的胶囊，选中项带柔光环；
  `renderToDataUrl` 用对应主题的 `sceneBg` 覆盖背景再回读，三种背景导出的是三张不同的图。
- **JSON 导入**：作品库右上角「导入」触发系统文件选择框（这一步由操作系统负责，无法用手势完成），
  读入后校验 `strokes/segments/{x,y,z}`、材质 id、数值范围，合法则作为**新作品**入库，
  非法则一句 "That file is not an AirDraw piece" 拒绝，不留半成品。
- **自检覆盖新增**：设置（开关即时生效 + 写回偏好 + 捏合关闭 + 列表可用捏合拖动滚动）、
  作品库删除（短捏只浮出确认、长按确认环才真的少一张且只少那一张）、
  导出（三种背景、分辨率不低于画布、画布不变）、导入（合法与非法各一条）。
- **写测试时挖出来的一条产品行为**：把惯用手设成「左手」而画面里只有右手时，主手选择正确地不接管
  那只右手——于是光标静止，而顶部只说 "Show your hand"，用户看不出自己"做错了什么"。
  行为本身是对的（`USER_GUIDE.md` 的常见问题里写了恢复步骤），定向提示排进第五阶段；
  自检因此改用合成手真实存在的那一侧（Right），否则测试会把自己的会话冻死——
  这正是第三阶段那次"摄像头根本没开"的同构教训：**测试要测真路径，也要用得起真路径的前提**。

### 30 分钟长跑（`SOAK_MS=1800000 npm run e2e`）

**阶段 A：23 个「写 24 笔 → 清空」周期，跨 1807 秒**

| 指标 | 画满时 | 清空后 |
| --- | --- | --- |
| draw calls | 4–5（预算 8，最差 5） | 2 |
| geometries | 13 | 11 |
| scene children | 8–9 | 6 |

| 72 | 7 | 15 | 131,212 | 865 |
| 96 | 8 | 16 | 144,280 | 545 |

墨量预算把第 96 笔的边际成本压到第 24 笔的 28%（1944 → 545 三角形）；清空后回到 calls 2 / geo 11。
剩下的帧率下降（20 → 9）是软件光栅的吞吐上限（本机 headless SwiftShader 约 10k 三角形/fps），
同机真实 GPU 上渲染实测 61–74 fps。

**长跑期间同步验证**：零控制台错误、零 pageerror；`debugInternals` 的
`drawingAllowed / inspectMode / penDown` 在每个周期都回到应有状态——
这正是抓出"剪刀手一闪误进查看模式"那个缺陷的地方（见第 9 节第 16 条）。

## 12. 剩余技术债

- 教程与说明书的内容仍是硬编码中文，没有 i18n 层。
- 作品库没有重命名与排序；缩略图与原图共用一次回读，超大画布时导出仍可能掉帧。
- **导入 JSON 的最后一步依赖操作系统文件框**：AirDraw 只能用手势打开它，选文件必须由鼠标/键盘完成，
  完全脱机导入（例如从作品库直接读剪贴板）没有做。
- 设置列表超过一屏，只能靠捏合拖动滚动（没有滚动条，这是刻意的），缺一个"跳到某一节"的导航；
  底部几项在没滚动时位于画面最边缘，手势很难命中。
- 粒子开场与正式画布是两个 WebGL 上下文（切换时前一个已 dispose），在只允许 8 个上下文的
  老浏览器上值得合并成同一个场景。
- 手势翻页的 70 px 阈值没有按屏幕高度缩放；小屏上偏灵敏。
- 自检断言与 `data-testid` 强耦合，界面改名必须同步改测试（换来的是测试不会静默通过）。
- 仍未做云端同步与多设备（按需求属于第五阶段之外）。

## 13. 第五阶段建议

1. **真实人手的产品级标定**：不同肤色、光照、遮挡下完整走一遍教程/说明书/作品库/设置，
   并据结果标定 `src/config.ts` 里的阈值（合成手能保证逻辑正确，不能代表人体工学舒适）。
2. 手离摄像头过近/过远时的**方向性提示**（现在只有"看不见手"这一类提示，深度本身是结构性约束）。
3. 把开场粒子与工作室收进同一个场景，消除双上下文，让 "Hello" 成为可复用的转场语言。
4. 作品库增强：命名、标签、排序、批量导出、导入后直接继续编辑（不必先入库）。
5. 文字识别与 3D 文字挤出；笔迹转字形。
6. TensorFlow.js `hand-pose-detection` provider 与双引擎对比。
7. 副手作为第二根手指：真正的双手缩放/平移/橡皮组合。
8. 光标前馈预测（补偿大幅移动时的收敛延迟）。
9. i18n：抽出教程与说明书的语言包；可访问性：键盘与指针兜底路径的焦点顺序、色觉友好的配色核对。
